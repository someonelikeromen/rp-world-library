# RP Achievement

主角专属外挂式成就系统。用于在 RP 中处理隐藏成就、待领取奖励、多重骰子即时生成奖励候选、原著奖励核实、最低使用门槛补足和多世界战斗框架落盘。

## 触发条件

- 用户启用成就系统。
- 剧情达成可能触发成就的关键节点。
- 用户要求查看光屏、查看已达成成就、查看当前人物状态、查看可领取奖励。
- 用户要求领取成就奖励。

## 核心规则

- 只给主角，不给 NPC。
- 默认隐藏；光屏需要主角主动呼出。
- 光屏只显示：已达成成就、当前人物状态、可领取奖励。
- 系统没有主动能力，不主动战斗、防御、治疗、传送、预警或干预剧情。
- 奖励必须手动领取，未领取前不生效。
- 奖励必须是原著明确出现的完整奖励；奖励内容与成就内容无关。
- 已归档世界不需要联网核实作品存在；未归档世界和随机动漫 / 游戏世界必须联网核实作品和具体奖励存在。
- 已有奖励不能重复。
- 奖励范围以当前世界等级锚点动态计算；评级必须先读取多世界评价方式 `rp-combat/framework/02-rating/02-evaluation-method.md`，再读取评级体系 `rp-combat/framework/02-rating/03-rating-system.md`，不得只按 N0–N24 表、作品名气或称号定级。

- 能量门判定必须读取完整经历链：当前世界、`memory/world-history.md`、角色卡 `combat/world-adaptation.json` 和已经历世界列表。不能只根据当前场景判断。
- 当前世界与所有经历世界均明确无能量体系/无能量接触时，抽到能量依赖奖励必须重抽；任一当前或历史世界存在有效能量接触，则允许进入候选但仍需核实、去重和适配。
- 每次成就奖励领取造成世界适配、能量接口、能力/资源/抗性变化时，必须同步更新经历链与 `worldAdaptation`。
- 若兑换系统启用并选择成就联动，成就系统随机原著奖励流程关闭；成就达成后直接转为奖励点并写入 `progression/exchange.json`，成就记录仍写入 `progression/achievements.json`。

## 执行流程

1. 判定成就是否触发；未触发不提示。
2. 成就触发时只输出简短提示：

```text
【成就达成：成就名】
【奖励待领取】
```

3. 生成世界 `.rd100`：
   - 已归档世界每个 3 个位置。
   - 未归档世界每个 2 个位置。
   - 其余位置用随机动漫 / 游戏世界填充。
   - 位置必须随机打散。
4. 用 `packages/rp-achievements` 和 `packages/rp-random` 执行随机、即时候选生成与校验。
5. 命中未归档或随机动漫 / 游戏世界时，先联网核实作品和奖励存在。
6. 命中世界后即时生成奖励候选；奖励内容不按成就主题定向。
7. 命中重复奖励时重骰。
8. 奖励进入 `pendingClaim`。
9. 主角主动领取后，执行最低使用门槛补足。
10. 将奖励、补足、状态、战斗评级影响写入对应角色卡模块：`achievements`、`abilities`、`resources`、`knowledge`、`inventory`、`combatLog`、`worldAdaptation` 等。

## 光屏输出限制

主动呼出光屏时，只显示：

1. 已达成成就。
2. 当前人物状态。
3. 可领取奖励。

禁止显示：未达成成就、隐藏触发条件、即时候选记录、未命中骰表、未来奖励、NPC 全知状态、世界隐藏真相。

## 奖励内容与成就内容解耦

- 成就只提供奖励生成资格、成就等级和领取状态。
- 奖励题材、作品、类型和具体内容不由成就名称、条件或剧情主题决定。
- 奖励内容由即时随机流程生成：当前世界等级 → .rd100 世界 → 奖励类型 → 原著候选 → 核实 → 去重。
- 不能因为成就是战斗/社交/探索成就，就定向给战斗/社交/探索奖励。
