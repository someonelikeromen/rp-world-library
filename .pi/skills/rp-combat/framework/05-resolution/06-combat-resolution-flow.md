## 6. 固定最小战斗判定流程

战斗判定不由代码完成，但需要固定一个最小流程。GM / agent 必须至少按此流程思考，可根据复杂度添加额外步骤。

### 6.1 最小流程

```text
1. 确认交战对象与战斗目标
2. 为每个战斗对象建立相同结构的评级面板
3. 区分综合评级、攻击面、防御面、反应、机动、感知、精神、特殊机制、抗性、资源
4. 确认双方基础属性差距
5. 确认双方可用能力与资源
6. 确认能力效果、消耗、限制与外在表现
7. 确认词条、相性、抗性与特殊机制
8. 确认环境与势力规则影响
9. 判定本轮结果与代价
10. 更新状态、资源、伤势、位置、关系与剧情后果
```

### 6.2 可添加流程

根据战斗复杂度，可以添加：

- 先手判定: Reaction 差距 ≥ 2 级 → 强制先手/强制受击，无法回避。同级 → 同时行动或按 perception 微调。
- 情报差判定。
- 战术准备判定。
- 偷袭/伏击判定。
- 多人配合判定。
- 领域/结界/地形控制判定。
- 士气与精神压力判定。
- 后援与势力介入判定。
- 战斗余波与公众影响判定。

### 6.3 战斗结果描述等级

战斗判定时需要按动作类型选择对应评级面，而不是直接比较综合评级。

示例：

```text
攻击命中判定：攻击方 reaction/control/perception + 技能特性 vs 防御方 reaction/mobility/perception。
伤害穿透判定：攻击方 offense + 词条 + 穿透机制 vs 防御方 defense/durability + 对应抗性。
精神攻击判定：攻击方 mental/hax + 词条 vs 防御方 mental + 精神/灵魂抗性。
消耗战判定：双方 resource + durability + recovery + control。
偷袭判定：攻击方 concealment/perception/control vs 防御方 perception/reaction/预警能力。
```

战斗结果不只输出胜负，应输出程度：

```text
无效
轻微影响
有效压制
势均力敌
明显优势
重创
击溃
秒杀
规则性胜利
战术性撤退
代价性胜利
```
