# 事件概率引擎 (Event Probability Engine)

> 来源: 型月引擎评审 A4  
> 用途: RP 中动态事件涌现——避免"到了第X轮固定触发Y事件"的僵硬设计

## 原则

静态事件表（"3天后下雨""5天后来刺客"）缺少涌现性。

事件概率应随剧情动态演化，高概率事件应排斥低概率事件干扰。

## 引擎机制

### 1. 事件池

事件按类型分池：

| 类型 | 说明 | 示例 |
|------|------|------|
| 危机 | 熵增事件(死亡/破坏/暴露) | 敌人来袭/身份暴露/魔力暴走 |
| 奇遇 | 熵减事件(救援/发现) | 遇到盟友/发现线索/获得道具 |
| 日常 | 中性事件 | 天气变化/路人事件/日常作息 |
| 情感 | 关系事件 | 误会/告白/信任危机/羁绊深化 |

事件池基于 `[当前时间 + 地点 + 好感度 + 全局状态]` 动态生成。

### 2. 独裁阈值

```
IF 任意事件概率 ≥ 80%
  → 排他性法则: 该事件锁定，其余事件概率冻结
  → 高概率事件成为剧情主轴，不被低概率噪音干扰
```

### 3. 常规判定

```
IF 无事件 ≥ 80%:
  FOR EACH 事件:
    Roll d100 vs 事件概率
    IF 通过 → 该事件触发，加入剧情队列
    IF 失败 → 事件概率 + (10%~20%) 累积
    # 累积触发: 一直不滚出的事件会越来越高概率
```

### 4. 逻辑顺位

冲突事件按熵增优先级排序：

```
熵增事件 (死亡/破坏) > 熵减事件 (救援/治愈) > 日常 > 情感
```

当多个事件同时触发时，高顺位事件优先占据剧情注意力。

### 5. 触发冷却

同一事件触发后进入冷却：

```
触发后: 概率重置为 5%
冷却期: N 轮内不再进入事件池
冷却结束: 恢复基准概率 (10%~30%)
```

## 使用方式

在 RP 中，每轮或每次场景切换时运行：

```
1. 生成当前场景的事件池（基于时间/地点/状态）
2. 对 pool 中事件做概率判定
3. 独裁阈值检查
4. 逻辑顺位排序
5. 将触发事件注入叙事
6. 未触发事件概率累积
7. 已触发事件进入冷却
```

## 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 独裁阈值 | 80% | 达到后锁定 |
| 累积步长 | 10%~20% | 未触发时每次增加 |
| 冷却轮数 | 5 | 触发后冷却期 |
| 基准概率 | 10%~30% | 冷却结束后恢复值 |
| 事件池上限 | 8 | 单次判定最大事件数 |
