# RP Life System Tree · 生命系统树规则

生命系统树是主角专属科技 UI 外挂。它使用奖励点点亮或记录通过剧情学习/修行自然达成的真实能力节点；每个节点必须标注来源世界观，禁止原创无来源节点。

## 1. 基础规则

- 主角专属，不给 NPC。
- 默认关闭，必须用户明确启用。
- 科技 UI。
- 与兑换系统默认互斥启用。
- 使用 `1级奖励点`、`2级奖励点`、`3级奖励点`，并允许扩展更高等级。
- 世界适配不做网状；必要变化只写入 `world-adaptation.json` 和 `memory/world-history.md`。

## 2. 显示规则

生命系统树只显示主角当前综合评级 +1 范围内的内容。

禁止显示：

- 隐藏节点轮廓。
- `???` 节点。
- 未搜索能力基点和树。
- 导航入口、分类入口、空节点。
- 超过综合评级 +1 的节点。
- GM-only、NPC 秘密、原著未来情报。

## 3. 能力基点

基点必须是能力基点，即真实能力、体质、特性、技艺、能量基盘、生命变化或基础状态。

允许：人类身体、人类灵魂、基础格斗、基础枪械、基础急救、生命感知、微弱再生、灵魂稳定、原著能量基盘等。

禁止：恢复类入口、N3层入口、生命干涉索引、防御类分支入口、导航节点、分类节点、文件夹节点、空节点。

系统内部可以有索引，但不可展示、不可点亮、不可进入剧情。

## 4. 来源世界观

每个节点必须有 `sourceWorld`，包括基础节点、自学节点、原著能力节点和剧情觉醒节点。

- 主角基础节点：标注出身世界或 `现实世界 / 普通人类基线`。
- 自学节点：标注学习发生的世界，并记录 memory 证据。
- 原著能力节点：标注原作品世界；已归档用 `world_query` ref，未归档双来源验证。
- 剧情觉醒节点：标注事件发生世界和 memory 事件引用。
- 禁止 `sourceType: original`。

## 5. 获取方式

节点可通过以下方式获得：

| 模式 | 说明 |
|---|---|
| `inherent` | 主角本来就有 |
| `currency` | 消耗奖励点点亮 |
| `selfTraining` | 学习/训练/修行自然达成 |
| `storyAchievement` | 剧情重大事件自然解锁 |
| `hybrid` | 训练进度 + 奖励点折扣补足 |
| `sourceAcquisition` | 传承、教学、道具、契约等获得 |

自然达成可 0 成本；折扣必须有剧情证据。

## 6. 发点来源

只允许：

- 战胜强敌。
- 对世界造成影响程度。
- 剧情偏转程度。

禁止：金钱购买、出售物品、资源转换、献祭材料、普通任务刷点、日常训练刷点、重复劳动刷点。

## 7. 定价

沿用兑换系统价格表。

- 起点 / 初始解锁：节点自身 N 级完整价格。
- 升级：目标 N 级完整价格 - 当前阶段 N 级完整价格。
- 折扣：最终价格 = 原价 × (1 - 折扣率)，折扣必须有 evidenceRef。
- 完全自学/剧情达成：0 成本。

## 8. 多世界评价

节点评价必须先读：

```text
.pi/skills/rp-combat/framework/02-rating/02-evaluation-method.md
.pi/skills/rp-combat/framework/02-rating/03-rating-system.md
```

节点必须含：

```json
{
  "evaluationMethod": "multi-world-evaluation-method-v1",
  "ratingSystem": "multi-world-rating-system-n0-n24-v1",
  "pricingRating": "N0",
  "basis": "",
  "evidence": []
}
```

## 9. 搜索与动态生成

未点亮能力基点和树必须用户主动搜索。

搜索流程：

```text
搜索 → 检查显示上限 → 查共享图 → 查归档/联网 → 来源审核 → 多世界评价 → 写入共享图 → 返回可显示真实节点
```

动态生成只允许生成真实能力节点，不允许原创、导航、分类或过渡节点。

## 10. 双写

点亮、升级、自学达成、发点、动态生成节点时，应按情况更新：

- `progression/life-system-tree.json`
- 具体角色卡模块
- `memory/world-history.md`
- `memory/user.md`

不可只写账本或只写 memory。
