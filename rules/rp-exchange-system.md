# RP Exchange System · 主角专属多世界兑换系统

兑换系统是一个可选外挂模块。它以多世界战斗框架为定价和落盘基础，让主角消耗奖励点兑换完整的体质/血统、能量基盘、能力、技艺传承、物品、知识和限定契约。

## 1. 系统定位

- 主角专属，不给 NPC。
- 默认关闭，必须由用户明确启用。
- 与成就系统并列；若二者联动，则成就奖励直接转化为奖励点。
- 系统不主动战斗、防御、治疗、传送、预警或替主角选择兑换项。
- 系统自带能力仅限：基本语言、初始身份、状态/兑换面板显示。

## 2. 货币：奖励点

奖励点按等级命名：

```text
1级奖励点（最低级）
2级奖励点
3级奖励点
4级奖励点
5级奖励点
……
```

默认进位：

```text
1000 个低一级奖励点 = 1 个高一级奖励点
```

底层可保存多级余额；显示时按高位到低位展示。

## 3. 获取方式

奖励点只能来自重大剧情影响：

- 完成重大事件。
- 击败强敌。
- 改变原著剧情。
- 对世界造成大规模影响。
- 对世界造成长时间影响。
- 解决世界级危机。
- 改变势力格局。
- 扭转关键人物命运。

禁止来源：

- 资源转换。
- 金钱购买。
- 出售战利品。
- 献祭材料。
- 普通任务刷点。
- 日常训练刷点。
- 重复劳动刷点。

## 4. 价格规则

价格只和兑换项自身层级有关。

价格不得受以下因素影响：

- 主角当前强度。
- 当前世界强度。
- 当前世界顶尖水平。
- 稀有度。
- 唯一性。
- 来源世界强弱。
- 适配当前世界程度。
- 是否契合主角。
- 是否容易使用。

高强度兑换仅通过价格区分，不增加额外限制。

禁止因为兑换项太强而：

- 设置前置条件。
- 增加适配期。
- 弱化能力。
- 拆成碎片。
- 只给试用版。
- 禁止在低级世界使用。

定价必须先估价后查表：

```text
来源验证 + 完整性确认
→ 依据多世界战斗/评价框架评估兑换项自身表现和作用上限
→ 得出兑换项自身 N0–N24 层级
→ 按该层级查奖励点价格表
```

`price` 类查表动作只接受已经完成多世界评价框架估价的 N 层级；不得跳过估价直接随意指定层级。
## 5. 支持兑换类型

### 5.1 体质 / 血统类

包括血统、种族、体质、器官、天赋、生命形态、灵魂性质、特殊身体结构。

### 5.2 能量基盘类

包括魔力、查克拉、灵力、咒力、念、小宇宙、气、斗气、仙力、神力接口等使用某体系的基础。

### 5.3 基于基盘的能力类

包括忍术、魔术、咒术、灵压系能力、念能力、依赖特定能量体系的术式、权能、技能。

### 5.4 不基于基盘的肉身 / 灵魂 / 技艺流派传承类

包括纯肉体能力、再生、感官、反射、灵魂强度、精神抗性、直觉、格斗术、剑术、枪术、暗杀术、武术、身法、弓术、锻体法、不依赖特殊能量的完整技艺体系或完整职业/流派传承。

### 5.5 物品道具类

包括武器、防具、神器、药物、魔导器、科技装备、消耗品、材料、载具、仪式道具。

### 5.6 知识类（不包括情报）

允许技术、理论、修炼、医疗、锻造、学科、工艺、能力体系知识。

禁止兑换：

- 当前剧情情报。
- 原著未来剧情情报。
- NPC 秘密。
- 世界隐藏真相。
- 敌方弱点情报。
- “下一步该怎么做”式攻略。

### 5.7 契约类

仅包括三类：

1. 使魔契约。
2. 召唤指定人物契约。
3. 队友契约：绑定后可一起穿越世界。

队友契约不等于强制洗脑；关系表现仍应符合契约内容、人物性格与剧情逻辑。

## 6. 禁止系统类兑换

不支持：

- 能量适配服务。
- 语言解析服务。
- 身份锚定服务。
- 能力封装服务。
- 装备兼容服务。
- 因果伪装服务。
- 系统修复。
- 系统强化。
- 系统代办。
- 系统保护。

## 7. 完整性规则

兑换项必须完整。

禁止：

- 碎片。
- 残缺版。
- 试用版。
- 弱化版。
- 单独一招。
- 单独一页传承。
- 单独一个血统片段。
- 把原本完整的内容拆成多个低价项。

允许：

- 原著中独立存在的完整阶段。
- 原著中独立存在的完整形态。
- 原著中独立存在的完整流派。
- 原著中独立存在的完整职业模板。
- 原著中独立存在的完整契约对象/契约类型。

## 8. 来源验证规则

### 已归档世界

- 优先用 `world_query` 查询。
- 记录 ref/sourceRef。
- 不强制联网验证作品存在。
- 仍需确认兑换项在归档资料中存在。

### 非归档世界

必须至少双来源验证。

每个来源记录：

- URL。
- 标题。
- 抓取时间。
- 摘要。
- 证明点。

两个来源都必须证明：

- 作品存在。
- 兑换项存在。
- 兑换项是完整内容。
- 描述没有重大冲突。

来源不足或冲突时不可兑换，标记为 `verificationStatus: blocked` 或 `pending`。

## 9. 成就系统联动

若启用成就联动：

```text
成就达成
→ 根据成就等级发放奖励点
→ 写入 progression/exchange.json
→ 成就本身仍写入 progression/achievements.json
→ 主角之后自行兑换
```

联动模式下，成就系统原随机奖励流程关闭。

## 10. 显示边界

兑换面板允许显示：

- 奖励点余额。
- 当前可兑换项。
- 已完成兑换。
- 待确认兑换。
- 来源验证状态。
- 主角当前状态摘要。

禁止显示：

- 未验证的非归档兑换详情。
- 剧情隐藏情报。
- 原著未来剧情情报。
- NPC 秘密。
- GM-only 信息。

## 11. 落盘规则

每次兑换必须写入：

- `card/<protagonist>/progression/exchange.json`：余额、交易、来源验证、兑换记录。
- 对应角色卡模块：能力、资源、物品、知识、契约、体质等。
- `card/<protagonist>/combat/world-adaptation.json`：跨世界适配、能量基盘、同行契约摘要。
- `memory/world-history.md`：来源世界、兑换内容、跨世界长期影响。

不可只写 memory，也不可只写角色卡。
