# 数据归档循环规则

## 原则

每卷数据的提取必须经过完整的 A→B→C→B 迭代循环，确认 **零问题** 后才能进入下一卷。

## 循环流程

```
A（工人：提取数据）
    ↓ 完成
B（审核：对照原文检查）
    ↓ 输出 issues[]
    ├── issues = [] → 归档 → 进下一卷
    └── issues > 0
            ↓
        C（修复：按 issue 清单修改）
            ↓ 完成
        B（重新审核：检查修复结果）
            ├── issues = [] → 归档 → 进下一卷
            └── issues > 0 → 回到 C（循环直到 issues = 0）
```

## 执行规则

1. **禁止跳过**：不允许在仍有 issue 的情况下进入下一卷
2. **最小修复**：C 只修 issue 中指出的问题，不做额外优化
3. **重新审核**：C 修复后必须重新走 B 审核
4. **零问题归档**：只有 B 输出 `issues: []` 时，才能标记该卷完成
5. **父进程控制**：迭代循环由 parent 手动控制，禁止子 agent 自动循环

## 归档标记

每卷完成时：

```
vol-XX: ✅ 完成
  文件数: N
  审核轮次: X（A→B→C→B 循环次数）
  最终状态: issues = 0
```
