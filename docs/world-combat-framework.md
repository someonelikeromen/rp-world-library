# 多世界战斗与数值框架规划

本文记录多世界 RP 框架中的世界设定、力量体系、战斗力评级、属性、能力与战斗判定规划。

核心定位：

- 这是一个沙盒多世界框架，不预设固定剧情命运。
- 世界记录自身客观规则、力量体系、势力与环境。
- 不默认存在命运、世界压制、剧情锁定。
- 不默认压制外来能力；只有当某世界设定中明确存在排斥、封锁、禁魔、法则压制等机制时才生效。
- 战斗判定由 GM / agent 根据规则进行，不由代码自动完成。
- 数值用于辅助一致性，不用于机械替代叙事判断。

---

## 1. 世界数据框架

每个世界应记录其自身的力量体系、势力、环境与规则，而不是被统一模板强行抹平。

### 1.1 世界基础信息

建议字段：

```json
{
  "worldId": "",
  "worldName": "",
  "genre": [],
  "summary": "",
  "sandboxPrinciple": "剧情不固定，角色行动与事件自然演化。",
  "hasFixedFate": false,
  "foreignPowerSuppressionDefault": false
}
```

说明：

- `hasFixedFate`：大多数世界为 `false`。只有世界观明确有命运、剧本、世界线收束时才为 `true`。
- `foreignPowerSuppressionDefault`：默认 `false`。除非该世界设定中明确有禁魔、排异、法则压制等。

### 1.2 力量体系列表

一个世界可以有多个力量体系。

例如：

```json
{
  "powerSystems": [
    {
      "id": "martial-arts",
      "name": "武道",
      "category": "body-technique",
      "principle": "通过肉体锻炼、技法、气血调动形成战斗力。",
      "energySource": "self",
      "hasExternalEnergy": false,
      "externalEnergyName": null,
      "energyTraits": [],
      "levelMapping": []
    },
    {
      "id": "mana-magic",
      "name": "魔法",
      "category": "external-energy-control",
      "principle": "通过精神模型与术式结构调动外界魔力。",
      "energySource": "external",
      "hasExternalEnergy": true,
      "externalEnergyName": "魔力",
      "energyTraits": ["可塑性高", "受环境浓度影响", "可被术式约束"],
      "levelMapping": []
    }
  ]
}
```

### 1.3 力量体系等级映射

每个本地力量体系需要说明其本地等级对应通用评级体系的哪个范围。

```json
{
  "levelMapping": [
    {
      "localLevel": "初级魔法师",
      "description": "能稳定施展低阶术式。",
      "universalRange": {
        "rank": "街头级",
        "minScore": 80,
        "maxScore": 150
      },
      "typicalAttributes": {
        "output": "D",
        "durability": "E+",
        "reaction": "D",
        "control": "C",
        "perception": "D+",
        "mentalStrength": "C",
        "computation": "C+"
      }
    }
  ]
}
```

注意：

- **levelMapping 是强制要求**，每个世界归档时必须为每个 powerSystem 填写。
- 本地等级不是绝对战力，只是常见范围。
- 同等级角色可因能力、经验、道具、相性差异产生巨大差别。
- 映射应允许范围，而非单点数值。
- 参考: 型月世界 `curated/world-rules/combat-framework-mapping.md` 含完整的 Fate N0-N24 映射示例。

### 1.4 势力与准则

世界需要记录主要势力、制度、准则与禁忌。

```json
{
  "factions": [
    {
      "id": "",
      "name": "",
      "type": "academy / guild / empire / cult / corporation / clan / loose-network",
      "summary": "",
      "powerSystemAffinity": [],
      "publicRules": [],
      "hiddenRules": [],
      "attitudeToOutsiders": "neutral",
      "knownMembers": []
    }
  ]
}
```

准则可以包括：

- 世界公开法律。
- 超凡者内部规则。
- 势力禁忌。
- 决斗、战争、交易、传承、禁术相关约束。

## 2. 通用战力评级体系

通用评级采用“汪吧评级体系”的思路：以破坏规模、作用范围、速度、耐久、特殊能力等进行综合判断，并进行数值化。

本项目需要建立一个项目内可用的“汪吧风格通用评级表”。

### 2.1 通用评级原则

- 评级是跨世界比较工具，不替代本地等级。
- 评级必须数值化，便于角色、能力、道具和世界体系之间做范围映射。
- 评级不能只看破坏力，还需结合出力、耐久力、反应力、控制力、感知力、精神强度、运算力、能力效果、抗性、战斗经验、相性。
- 基础属性只记录角色肉身/自身常态裸值，不混入能量、能力、技能、装备带来的加成。
- 能量、能力、技能、装备造成的常态强化、临时强化、爆发、透支、削弱，必须作为独立状态记录。
- 精神强度主要用于对抗或支撑精神/灵魂攻击、精神/灵魂类能力、污染、控制、心智压力等。
- 抗性主要由生命等级、特殊能力、防护道具、体系特征决定，不作为普通基础属性直接平均。
- 词条需要分等级，不只是有/无。

### 2.2 通用评分结构

本项目使用“项目内汪吧风格评级表”，不伪称为某个社区的官方原表。设计原则参考战力讨论中的“扒皮”思路：以可验证表现、作用范围、破坏尺度、创造/支配尺度、速度与抗性表现作为证据，禁止只凭称号、设定吹词或角色台词直接定级。

评分结构：

```text
评级名 + 子级 + 数值区间 + 表现力标注 + 证据要求
```

数值使用指数式扩张，不追求现实物理精确换算，只用于跨世界内部一致性。每一级内部保留低/中/高/巅峰四段。

### 2.4 扒皮式评级方法

评级时必须拆解证据，而不是直接引用称号。

最小扒皮流程：

```text
1. 明确对象：角色、能力、道具、形态、一次性事件分别评级。
2. 区分常态/强化/爆发/透支/蓄力/仪式/外部支援。
3. 确认出手速度：常态评级只采用标准出手窗口内的表现。
4. 找最高直接表现：实际造成、承受、创造、支配了什么。
5. 找稳定表现：该表现能否复现，是否需要特殊条件。
6. 找范围证据：作用于个人、城市、星球、宇宙、多宇宙还是高维结构。
7. 找机制证据：是纯破坏、规则改写、概念支配、信息覆盖、叙事权限还是外部道具。
8. 排除同名不同义：神明、魔王、概念、维度、世界、宇宙等词不自动等同高评级。
9. 排除水分：称号、夸张台词、未兑现设定、环境连锁、借用外力。
10. 非明确证据不上升规则级/概念级/高维级。
11. 记录结论：给出常态评级、最高评级、条件评级和争议点。
```

#### 标准出手窗口

常态攻击/防御评级只采用“标准出手窗口”内可完成的表现。

```text
标准出手窗口 = 同水平战斗中 2 次正常出手速度之内
```

含义：

- 如果同级角色通常能在 1 秒内完成一次正常攻击，则 2 秒内完成的招式可计入常态可用战斗表现。
- 超过该窗口的蓄力、咏唱、布阵、仪式、环境准备，不计入常态评级，只能计入条件评级。
- 可以在战斗中通过掩护、控场、队友配合完成的长蓄力，需要记录为“战术条件评级”。
- 开局前已准备好的陷阱、阵地、仪式、蓄能道具，不提升角色常态评级，只记录为场地/准备优势。

示例：

```text
某角色常态拳脚为 N5 街区级。
大招蓄力 30 秒可打出 N8 区域级。
若同水平战斗中 2 次正常出手窗口约为 3 秒，则 N8 只能记为 conditionalRating，不能记为 baseRating。
```

#### 同名不同义排除

评级不能按词语名号自动套高位含义。

示例：

- “神明”可能只是地方精灵，也可能是宇宙创造者，必须看表现。
- “魔王”可能只是军阀称号，也可能是世界级灾害，必须看表现。
- “概念”可能只是技能名称，也可能真能操作抽象概念，必须看机制证据。
- “维度”可能是空间方向、异空间、口袋空间、高维结构，必须区分语义。
- “宇宙”可能指星空、世界、单一时空连续体、多元集合，必须看上下文定义。

#### 明确证据优先

非明确证据不上升规则级、概念级、高维级、外层级。

只有出现明确表现或设定链路时，才允许提高机制层级：

- 明确作用于抽象规则，而不是普通能量攻击带特殊名字。
- 明确影响因果/时间线，而不是预判或高速行动。
- 明确支配灵魂/概念/信息，而不是造成精神伤害的比喻。
- 明确高维结构，而不是“更高境界”“超越凡人”这类修辞。

评级结果必须分栏：

```json
{
  "baseRating": "N7 城市级",
  "peakRating": "N9 国家/大陆板块级",
  "conditionalRating": "N12 行星级（需要仪式和外部能源）",
  "chargeTime": "30 秒，超过标准出手窗口",
  "combatApplicability": "需要队友掩护或提前布阵",
  "evidence": [],
  "limitations": [],
  "disputes": []
}
```

### 2.5 子级与数值段

每一级内部用四段描述：

```text
低段：刚进入该级，表现不稳定或范围偏小
中段：稳定达到该级常规表现
高段：该级中明显强者，可压制中低段
巅峰：接近下一级门槛，但仍未满足下一级证据
```

数值段按区间四等分。例如 N12 行星级 `256,000-511,999`：

```text
N12-Low   256,000-319,999
N12-Mid   320,000-383,999
N12-High  384,000-447,999
N12-Peak  448,000-511,999
```

### 2.6 高等级特殊说明

从 N18 开始，不能只按破坏力理解。

需要区分：

- 单体宇宙：一个完整时空连续体。
- 多宇宙：多个彼此独立的宇宙。
- 大型多元：大量独立宇宙集合。
- 无限多元：明确无限数量宇宙集合。
- 高维多元：存在比普通宇宙更高维的结构，并能有效作用。
- 复杂高维：多层嵌套、高维阶梯、超越单一高维轴。
- 外层/超维叙事结构：超越维度数量、时空集合或叙事层级。

高等级需要记录“作用对象”而不是只写等级：

```json
{
  "scaleTarget": "infinite-multiverse",
  "structureEvidence": "明确存在无限数量独立宇宙，并被同一能力同时重置。",
  "operationType": "reset",
  "isCombatApplicable": true,
  "conditions": []
}
```

### 2.7 原 2.3：战力分数不是单一攻击力

### 2.3 战力分数不是单一攻击力

综合战斗力应从多项维度估算，但综合评级不能替代分项评级。

```text
综合战力 = 基础属性表现 + 能力修正 + 道具修正 + 经验修正 + 相性修正 + 抗性修正
```

一个人物可能出现：攻击高、防御低、反应高、感知弱、精神抗性强、物理抗性弱等不均衡结构。战斗时必须区分各方面评级，不能只用综合评级判断胜负。

其中基础属性包括：

- 出力。
- 耐久力。
- 反应力。
- 控制力。
- 感知力。
- 精神强度。
- 运算力。

能力修正包括：

- 攻击能力。
- 防御能力。
- 移动能力。
- 控制能力。
- 治疗能力。
- 信息能力。
- 规则/概念能力。
- 特攻词条。
- 抗性穿透。

## 3. 基础属性框架

角色/单位的基础属性不使用传统 STR/AGI，而使用更贴近跨世界战斗表现的维度。

基础属性的原则：

- 只记录肉身/自身常态裸值。
- 不记录能量强化、能力强化、装备强化、技能架势、临时 Buff、爆发态、透支态。
- 所有非裸值变化进入 `modifiers`、`states`、`forms`、`buffs`、`debuffs` 或 `overload` 等状态结构。
- 基础属性用于判断角色在“不主动发动额外能力”时的常态表现。

### 3.1 核心属性

```text
Output          出力
Durability      耐久力
Reaction        反应力
Control         控制力
Perception      感知力
MentalStrength  精神强度
Computation     运算力
Fortune         运势/概率抵抗
```

`Fortune`: 对抗概率性效果（即死/因果干涉/暴击判定/命运操作）。不替代幸运技能或道具，仅作为裸值基准。

### 3.2 属性与评级挂钩

每项基础属性都需要能映射到通用评级表。属性评分不是独立体系，而是通用评级在不同维度上的分项表现。

```json
{
  "attributeRatings": {
    "output": {
      "rating": "N5 街区级",
      "score": 2600,
      "basis": "肉身常态全力一击可破坏街区级结构的一部分。"
    },
    "durability": {
      "rating": "N4 建筑级",
      "score": 1500,
      "basis": "肉身常态可承受建筑级冲击但会受伤。"
    },
    "reaction": {
      "rating": "N6 城镇级反应域",
      "score": 4200,
      "basis": "可在同级高速战斗中捕捉并应对城镇级对手的常态攻击。"
    }
  }
}
```

属性映射原则：

- `Output` 映射肉身常态攻击表现。
- `Durability` 映射肉身常态承受表现。
- `Reaction` 映射常态反应与身体执行表现，不等于移动速度全项。
- `Control` 映射对自身力量/能量/技巧的精细控制等级。
- `Perception` 映射发现、识别、追踪同级目标和异常的能力。
- `MentalStrength` 映射精神/灵魂对抗与支撑能力。
- `Computation` 映射战斗建模、术式计算、并行处理、学习解析能力。

同一角色不同属性可以跨级。例如：

```text
玻璃大炮：Output N8，Durability N4，Reaction N6。
高速刺客：Output N5，Durability N4，Reaction N8，Perception N7。
术式学者：Output N4，Control N8，Computation N9，MentalStrength N6。
```

综合战力需要以分项属性、能力、词条、抗性、资源、战斗经验共同判断，不能只取属性平均值。

### 3.4 属性解释

#### 出力 Output

角色肉身常态出力，不包含能量、能力、技能、装备、爆发、透支带来的额外输出。

包括：

- 常态肌肉力量。
- 常态身体发力效率。
- 不使用超凡强化时的物理打击基础。
- 不开启特殊形态时的搬运、冲撞、压制等肉身表现。

不包括：

- 能量炮、法术、灵压释放等能量输出。
- 技能倍率造成的爆发输出。
- 装备增幅。
- 临时 Buff。
- 透支身体或燃烧生命获得的输出。

#### 耐久力 Durability

角色肉身常态耐久，不包含护盾、铠甲、能量防护、技能减伤、特殊形态等外部或主动强化。

包括：

- 常态身体防御。
- 常态抗打击能力。
- 常态组织强度。
- 常态伤势承受。
- 常态体力与负荷承受。

不包括：

- 能量护盾。
- 装甲防护。
- 技能减伤。
- 再生能力额外效果。
- 透支状态下的硬抗。

#### 反应力 Reaction

角色肉身与神经系统的常态反应，不包含预知、感知技能、加速能力、时间系能力、装备辅助等加成。

包括：

- 常态神经反应。
- 常态身体执行速度。
- 常态战斗本能。
- 不依赖技能时的即时应对。

不包括：

- 预知未来。
- 时间减速/加速。
- 技能提供的反射增强。
- 装备辅助瞄准。
- 高速思维术式。

#### 控制力 Control

精细操控自身力量、能力、能量和战斗节奏的能力。

包括：

- 能量精密控制。
- 技能稳定性。
- 多线程操作。
- 降低消耗。
- 减少副作用。

#### 感知力 Perception

发现、识别、追踪、预警的能力。

包括：

- 五感强化。
- 能量感知。
- 灵觉。
- 杀意感知。
- 空间/因果/精神异常感知。

#### 精神强度 MentalStrength

用于对抗、承载或支撑精神/灵魂层面的攻击、能力、污染、控制和压力。

包括：

- 抗恐惧。
- 抗精神攻击。
- 对抗灵魂冲击。
- 支撑精神类能力发动。
- 支撑灵魂类能力发动。
- 保持自我。
- 忍耐痛苦。
- 抵抗污染、洗脑、魅惑、幻觉。

不等同于普通智力，也不等同于运算力。

#### 运算力 Computation

理解、计算、建模、快速学习和战斗推演能力。

包括：

- 法术模型计算。
- 战术推演。
- 多目标处理。
- 技术解析。
- 高速学习。

### 3.5 抗性处理

抗性不作为常规属性之一，而由以下来源共同决定：

- 生命等级。
- 身体结构。
- 灵魂结构。
- 能量体系特性。
- 特殊能力。
- 道具。
- 环境加护。
- 训练与经验。

抗性应以标签和等级记录，等级可与词条等级体系共用或映射：

```json
{
  "resistances": [
    {
      "tag": "mental-interference",
      "name": "精神干涉抗性",
      "level": "C",
      "source": "精神强度 + 训练",
      "notes": "对普通催眠和恐惧诱导有效，对高阶概念污染不足。"
    }
  ]
}
```

## 5. 跨世界能力适配规划

根据当前需求重写：不默认有世界压制。能力能否使用主要看能力自身依赖与当前世界是否提供对应条件。

### 5.1 保留规则

跨世界时：

- 身体层面可完全保留。
- 精神层面可完全保留。
- 灵魂层面可完全保留。
- 天赋可完全兼容。
- 基于自身本质的能力可保留。
- 需要外界交互、外界能量、世界法则支持的能力，视当前世界情况而定。
- 特殊能力可突破常规限制，但必须记录原理、条件和代价。

### 5.2 适配判断不等于压制

进入新世界时，不进行默认压制，而进行条件检查：

```text
1. 能力依赖什么？
2. 当前世界是否存在该资源或等价资源？
3. 使用者是否能感知、吸收、转化、调用该资源？
4. 能力原理是否需要某种世界规则承认？
5. 如果没有原资源，是否可由自身能量、道具、天赋、替代能源补足？
6. 如果世界明确存在排斥机制，才计算压制或反噬。
```

### 5.3 适配结果

```text
Full        完全可用
Equivalent 通过等价资源可用
Partial     部分可用，效果变化
SelfOnly    仅自身部分可用
Unavailable 条件缺失，无法发动
Rejected    被世界规则/环境明确排斥
```

示例：

```json
{
  "abilityId": "shadow-devour",
  "adaptation": "Partial",
  "reason": "当前世界存在阴影与负能量，但不存在原体系的暗影源海。可使用自身储备发动，恢复速度下降。",
  "changes": [
    "最大输出降低",
    "持续时间缩短",
    "侵蚀词条保留",
    "对灵效果保留"
  ]
}
```

## 6. 固定最小战斗判定流程

战斗判定不由代码完成，但需要固定一个最小流程。GM / agent 必须至少按此流程思考，可根据复杂度添加额外步骤。

### 6.1 最小流程

```text
1. 确认交战对象与战斗目标
2. 为每个战斗对象建立相同结构的评级面板
3. 区分综合评级、攻击面、防御面、反应、机动、感知、精神、特殊机制、抗性、资源
4. 确认双方基础属性差距
5. 确认双方可用能力与资源
6. 确认能力效果、消耗、限制与外在表现
7. 确认词条、相性、抗性与特殊机制
8. 确认环境与势力规则影响
9. 判定本轮结果与代价
10. 更新状态、资源、伤势、位置、关系与剧情后果
```

### 6.2 可添加流程

根据战斗复杂度，可以添加：

- 先手判定: Reaction 差距 ≥ 2 级 → 强制先手/强制受击，无法回避。同级 → 同时行动或按 perception 微调。
- 情报差判定。
- 战术准备判定。
- 偷袭/伏击判定。
- 多人配合判定。
- 领域/结界/地形控制判定。
- 士气与精神压力判定。
- 后援与势力介入判定。
- 战斗余波与公众影响判定。

### 6.3 战斗结果描述等级

战斗判定时需要按动作类型选择对应评级面，而不是直接比较综合评级。

示例：

```text
攻击命中判定：攻击方 reaction/control/perception + 技能特性 vs 防御方 reaction/mobility/perception。
伤害穿透判定：攻击方 offense + 词条 + 穿透机制 vs 防御方 defense/durability + 对应抗性。
精神攻击判定：攻击方 mental/hax + 词条 vs 防御方 mental + 精神/灵魂抗性。
消耗战判定：双方 resource + durability + recovery + control。
偷袭判定：攻击方 concealment/perception/control vs 防御方 perception/reaction/预警能力。
```

战斗结果不只输出胜负，应输出程度：

```text
无效
轻微影响
有效压制
势均力敌
明显优势
重创
击溃
秒杀
规则性胜利
战术性撤退
代价性胜利
```

## 8. 速度体系

速度必须拆分，不使用单一“速度等级”覆盖所有表现。

### 8.1 速度分项

```text

MovementSpeed      移动速度：常规跑动、飞行、位移速度

ThinkingSpeed      思维速度：分析、计算、决策速度
CastingSpeed       施法/蓄力/构筑速度
ProjectileSpeed    弹道/攻击飞行速度
Teleportation      瞬移/传送，不直接等同移动速度
```

### 8.2 速度判定原则

- 命中判定看 `ReactionSpeed`、`ActionSpeed`、`Perception`、技能轨迹和攻击范围。
- 追击/逃跑看 `MovementSpeed`、`TravelSpeed`、地形和续航。
- 法术对轰看 `CastingSpeed`、`Computation`、`Control`。
- 瞬移/传送单独记录距离、条件、冷却、锁定方式和可否被打断。
- 时间停止、时间加速、预知未来等不归入普通速度，应作为能力或特殊机制处理。

## 11. 能力与抗性碰撞规则

特殊机制碰撞不按名字大小决定，而按能力等级、抗性等级和驱动属性判定。

### 11.1 最小碰撞流程

```text
1. 确认攻击/效果词条
2. 确认防御方是否有对应抗性词条
3. 比较能力等级与抗性等级
4. 若等级不同，高等级一方占优
5. 若等级相同，比较对应驱动属性
6. 若仍接近，比较消耗、控制力、情报、环境和状态
7. 输出结果：无效 / 削弱 / 部分生效 / 完全生效 / 反噬
```

### 11.2 等级比较

```text
能力等级 > 抗性等级：效果可突破抗性，但可能被削弱
能力等级 = 抗性等级：进入驱动属性对抗
能力等级 < 抗性等级：效果被抵抗、偏转或大幅削弱
```

### 11.2.1 无效化阈值规则

从 Fate 对魔力体系提炼——当抗性等级足够高时可直接无效化低等级攻击。

```text
抗性等级 ≥ 攻击等级 + 2  → 完全无效化
抗性等级 ≥ 攻击等级      → 大幅减免（70-90%）
抗性等级 = 攻击等级 - 1  → 部分减免（30-50%）
抗性等级 ≤ 攻击等级 - 2  → 基本不减免
```

仅适用于"同类型"抗性（如 对魔力 只抵抗魔术，不抵抗物理攻击）。
跨类型抗性不适用此规则。

### 11.3 驱动属性

不同机制对应不同驱动属性：

```text
精神控制       MentalStrength / Control / Computation
灵魂攻击       MentalStrength / Soul-related resistance / Control
能量侵蚀       Control / Output / 对应能量资源
概念干涉       Control / MentalStrength / 机制等级
因果干涉       Computation / Control / 机制等级
时间能力       Control / Computation / 能力等级
空间能力       Control / Perception / Computation
信息干涉       Computation / Control / 对应信息抗性
肉体压制       Output / Durability
结界压制       Control / Resource / 术式结构
```

示例：

```text
B 级精神控制 vs B 级精神抗性：等级相同。
进入驱动属性对抗：攻击方 MentalStrength + Control，对防御方 MentalStrength + 对应抗性来源。
若攻击方控制力更高但资源不足，结果可判为“短暂部分生效”。
```

## 13. 证据等级

评级证据需要分级，防止把低证据当高证据。

```text
S 级：直接画面/直接表现，明确造成或承受结果
A 级：可靠旁白/设定书/系统说明，且不与表现冲突
B 级：可靠角色评价，有足够上下文支持
C 级：合理推导，基于已知规则和多次表现
D 级：称号、传闻、夸张台词、单次未验证说法
E 级：粉丝外推、语义误读、同名不同义
```

规则：

- 常态评级优先使用 S/A 级证据。
- B/C 级证据可辅助，但需要标注争议。
- D/E 级证据不能单独提升等级。
- 高维、概念、因果、外层级必须要求明确 S/A 级证据链。
