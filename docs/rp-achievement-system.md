# RP Achievement System · 主角专属外挂式成就系统

成就系统是一个**只给主角的专属外挂模块**。主角达成成就后，通过多重骰子即时生成来自本世界或其他世界、且在原著中明确出现过的完整奖励候选。

它的核心不是“纪念章”，而是“主角专属外挂奖励”：成就触发后，系统即时生成原著奖励候选并随机命中其中一个奖励；奖励默认进入待领取状态；主角手动领取后，如果当前不满足使用要求，系统会自动补足到能最低限度使用该奖励的程度；随后奖励通过多世界战斗框架翻译并写入角色卡模块。

成就系统默认隐藏，不主动显示光屏，不主动干涉剧情，没有任何主动能力。只有达成成就时会出现一次提示。

---

## 1. 核心定义

### 1.1 系统定位

成就系统用于：

- 给主角提供专属外挂式成长和跨世界奖励。
- 通过骰子从即时原著奖励候选池中抽取奖励。
- 记录成就、随机过程、奖励来源、原著依据、补足内容和落盘结果。
- 将跨世界奖励翻译成多世界战斗框架可处理的角色卡模块变化。

成就系统不用于：

- 发放原著没有明确出现过的奖励。
- 自造“这个世界应该存在”的能力、神器、体质、知识或系统物品。
- 把多个世界观机制拼成一个新奖励。
- 发放碎片、残卷、残缺传承、试用能力。
- 主动替主角行动、主动释放能力、主动干预战斗。
- 让奖励绕过角色卡模块和多世界战斗框架落盘。

### 1.2 核心循环

```text
成就触发
→ 成就提示
→ 多重骰子随机奖励
→ 即时生成并命中奖励候选
→ 奖励进入待领取状态
→ 主角手动领取
→ 检查使用条件
→ 自动补足最低使用门槛
→ 多世界战斗框架适配
→ 写入角色卡模块
→ 后续剧情中使用
```

### 1.3 硬规则

1. **主角专属**：成就系统只给主角，不给 NPC。
2. **默认隐藏**：所有成就、即时候选记录、随机过程、未达成条件默认隐藏。
3. **无主动能力**：系统不能主动行动、主动保护、主动攻击、主动释放奖励。
4. **手动领取**：奖励不会自动生效，必须由主角手动领取。
5. **原著明确出现**：奖励必须是原著中明确出现过的内容，不能依托世界观自行虚构。
6. **奖励本体完整**：奖励必须完整，不发碎片、残缺版、试用版或不完整传承。
7. **最低门槛补足**：如果当前角色不满足使用要求，系统必须补足到能最低限度使用该奖励的程度。
8. **强度受限**：奖励不得超过当前世界顶尖水平太多，并按当前世界等级动态映射到角色卡同款 N0–N24 汪吧风格评级。

---


### 1.4 成就与奖励内容解耦

成就只负责产生一次“奖励生成资格”和领取状态，不决定奖励内容。

- 成就名称、成就条件、成就剧情主题不得用于定向指定奖励题材。
- 成就等级只影响奖励生成的相对强度、可抽范围、风险和是否允许高危奖励。
- 具体奖励内容由即时随机流程决定：当前世界等级 → .rd100 世界 → 奖励类型 → 具体原著奖励候选 → 核实 → 去重。
- 即使成就来自战斗、社交、探索或日常突破，奖励内容也不需要与该成就主题对应。
- 若奖励与成就主题看似契合，只能视为随机结果，不得反推为系统按主题奖励。
## 2. 模块定位

### 2.1 可选独立模块

成就系统不默认并入统一角色卡必需模板，而是作为可选独立模块存在。

推荐路径：

```text
card/<character-id>/progression/achievements.json
```

建议模块别名：

```json
"achievements": "progression/achievements.json"
```

### 2.2 模块职责

成就模块负责记录：

- 成就列表。
- 成就等级。
- 隐藏状态。
- 多重骰子随机过程。
- 奖励来源与原著依据。
- 奖励本体与奖励类型。
- 奖励待领取状态。
- 最低使用门槛补足。
- 多世界战斗框架映射。
- 目标角色卡模块落盘状态。

具体奖励仍需同步写入对应角色卡模块，例如：

- `inventory`
- `attributes`
- `lifeProfile`
- `resources`
- `abilities`
- `resistances`
- `states`
- `knowledge`
- `relationships`
- `combatLog`
- `worldAdaptation`

## 3. 主角专属与隐藏显示

### 3.1 主角专属

规则：

- 成就系统只绑定主角。
- NPC 不能拥有同类成就系统。
- NPC 可以被成就影响，例如成为触发条件、关系后果、契约对象或奖励内容。
- NPC 不能获得系统光屏、系统提示、系统即时候选记录或系统补足。

### 3.2 默认隐藏

成就系统的所有内容默认隐藏。

隐藏范围包括：

- 未达成成就。
- 隐藏成就。
- 成就触发条件。
- 即时候选。
- 多重骰子未命中项。
- 待领取奖励的完整候选列表。
- 系统内部判定条件。

只有以下内容可以显示：

- 成就达成时的一次提示。
- 主角主动呼出光屏后，可查看已达成成就、当前人物状态、可领取奖励。
- 主角主动查看奖励时，只能查看已经生成的待领取奖励。
- 主角领取奖励后，可在当前人物状态中查看已领取奖励与当前适配状态。

### 3.3 光屏规则

- 光屏 / 面板默认不显示。
- 光屏需要主角主动呼出。
- 系统不会主动弹出完整界面。
- 成就达成时只出现提示，不自动展开光屏。

主角主动呼出光屏后，只显示三类内容：

1. **已达成成就**：只列出已经解锁的成就；未达成成就、隐藏条件、进度条默认不显示。
2. **当前人物状态**：只显示与主角当前可见状态相关的信息，例如生命状态、资源状态、已获得能力、适配状态、异常状态；不显示隐藏判定和未公开即时候选记录。
3. **可领取奖励**：只显示已经生成并处于 `pendingClaim` 的奖励；不显示未命中奖励、即时候选或未来奖励。

光屏禁止显示：

- 未达成成就列表。
- 隐藏成就触发条件。
- 即时候选记录内容。
- 多重骰子未命中项。
- 未来可获得奖励。
- NPC 状态全知信息。
- 世界隐藏真相。

提示格式建议：

```text
【成就达成：成就名】
【奖励待领取】
```

提示只说明成就达成与奖励待领取，不公开全部隐藏成就列表，也不公开未命中即时候选记录内容。
### 3.4 无主动能力

成就系统没有任何主动能力。

禁止：

- 主动替主角战斗。
- 主动替主角防御。
- 主动释放奖励能力。
- 主动传送、治疗、复活、预警。
- 主动改变 NPC 决策。
- 主动修改世界事件。

系统只做：

- 记录。
- 达成提示。
- 随机奖励。
- 待领取管理。
- 领取后的最低门槛补足。
- 状态落盘。

## 4. 原著依据规则

### 4.1 可进入即时候选的内容

允许进入即时候选的奖励必须满足“原著明确出现”。可收录：

- 原著明确登场的实物、装备、药物、材料、道具。
- 原著明确出现的体质、血统、器官、资质、能量接口。
- 原著明确出现的能力、术式、魔法、忍术、念能力、替身能力等。
- 原著明确出现的武学、流派、招式、呼吸法、控制法、修炼法。
- 原著明确出现的知识体系、语言、记忆、技术、理论。
- 原著明确出现的资源体系，如查克拉、念、气、咒力、魔力、灵压等。
- 原著明确出现的召唤物、契约对象、使魔、式神等。

### 4.2 禁止进入即时候选的内容

禁止收录：

- 原著没有出现过的原创神器、原创血统、原创术式。
- 只根据力量体系推导出的新招式。
- “系统道具”“一次性凭证”“世界通行证”“封印钥匙”等泛系统概念。
- “身份”“权限”“商店”“任务入口”“阵营通行”等泛权限概念。
- “世界适应补丁”“法则翻译器”“跨世界兼容槽”等抽象兼容概念。
- “法则理解”这类非原著明确奖励。

例外：如果某作品原著中确实存在同名或同功能的具体物品/机制，则按其原著形态收录，而不是作为系统泛用类型。

### 4.3 原著依据字段

每个奖励必须记录原著依据：

```json
{
  "canon": {
    "required": true,
    "sourceType": "manga|novel|anime|game|official-databook|official-setting",
    "work": "原著作品名",
    "appearsAs": "原著正式名称",
    "holderOrUser": "原著持有者/使用者，可为空",
    "evidence": "章节、卷数、集数、设定集条目或剧情场景摘要"
  }
}
```

如果暂时无法确认原著依据，该奖励不能进入即时候选。


### 4.4 未归档作品与随机动漫 / 游戏候选的联网核实

作品 / 世界候选不局限于已经归档的世界。

可用来源：

| 候选来源 | 含义 | 要求 |
|----------|------|------|
| `archivedWorld` | 已在本项目世界书中归档的世界 | 不需要联网核实作品存在；具体奖励仍需有原著依据 |
| `unarchivedWorld` | 从未归档进项目的作品或世界 | 必须联网查询核实作品与奖励真实存在 |
| `randomAnimeGameWorld` | 由模型其他随机动漫 / 游戏知识提出的候选 | 必须联网查询核实作品与奖励真实存在 |

联网核实规则：

- 已归档世界不需要联网核实作品存在。
- 如果候选作品 / 世界不在本项目归档中，必须先联网查询。
- 如果候选来自模型内置动漫、漫画、小说、游戏知识，也必须联网查询。
- 查询目标至少包括：作品是否存在、奖励名称是否存在、奖励是否确实在原著或官方资料中出现。
- 优先使用官方资料、出版社 / 游戏公司资料、官方设定集、原作百科、可信作品 Wiki；无法确认时不得进入即时候选。
- 若只确认作品存在，但无法确认具体奖励存在，则该奖励无效，重骰具体奖励或重骰作品。
- 联网核实只证明“存在”，不等于可以无条件高评级；战力仍必须先按多世界评价方式拆证据，再按当前世界等级锚点和汪吧 N 级计算。

核实记录建议：

```json
{
  "verification": {
    "required": true,
    "reason": "unarchivedWorld|randomAnimeGameWorld",
    "status": "webVerified",
    "checkedAt": "YYYY-MM-DD",
    "verifiedWork": true,
    "verifiedReward": true,
    "sources": [
      { "title": "来源标题", "type": "official|wiki|database|other", "supports": "work|reward|canonEvidence" }
    ]
  }
}
```

未归档世界通过联网核实后，可以作为本次抽奖的临时验证候选，不要求先完整归档到 `campaigns/`。后续如果反复使用，再考虑正式归档。

## 5. 奖励来源与命名

### 5.1 来源范围

| 来源 | 含义 | 处理方式 |
|------|------|----------|
| `currentWorld` | 当前世界奖励 | 使用上帝视角正式名称和完整奖励名 |
| `visitedWorld` | 已接触或已进入过的世界 | 使用上帝视角正式名称；角色认知可另行限制 |
| `unvisitedWorld` | 尚未进入剧情的其他世界 | 允许引用，但奖励记录必须写正式世界名和正式奖励名 |
| `canonIndex` | 原著奖励索引 | 只收录原著明确出现的条目 |

### 5.2 命名规则

奖励名称必须使用上帝视角正式名称，例如：

- `型月世界 · 魔术回路`
- `火影世界 · 替身术`
- `浪客剑心世界 · 飞天御剑流`
- `鬼灭世界 · 雷之呼吸`
- `全职猎人世界 · 念能力基础体系`

正文叙事可以限制主角当前理解，但系统记录必须保留正式名称、来源世界和完整奖励本体。

## 6. 奖励类型

奖励类型必须收窄，只保留原著中明确存在、可记录出处的内容。

| 奖励类型 | 示例 | 主要落盘模块 | 说明 |
|----------|------|--------------|------|
| `item` | 武器、防具、装备、药品、材料、原著道具 | `inventory` | 必须是原著明确出现过的实物或道具 |
| `constitution` | 体质、血统、器官、灵根、魔术回路、仙人体 | `attributes` / `lifeProfile` / `states` | 必须是原著明确存在的身体/血统/资质类要素 |
| `ability` | 异能、术式、忍术、魔法、念能力、替身能力 | `abilities` | 必须是原著明确出现过的能力 |
| `technique` | 武学、剑术流派、呼吸法、查克拉控制法、战斗技巧 | `abilities` / `knowledge` | 招式类默认附带所属流派、理论和训练前提 |
| `knowledge` | 原著明确存在的知识体系、语言、技术、记忆、修炼法 | `knowledge` | 不收录抽象法则补丁 |
| `resourceSystem` | 查克拉、念、气、咒力、魔力、灵压等资源体系 | `resources` | 若奖励依赖资源，自动补足最低资源和控制技巧 |
| `resistance` | 原著明确出现的抗性、免疫、净化、耐受特性 | `resistances` / `states` | 不能自造通用抗性 |
| `summonOrContract` | 原著明确存在的召唤物、契约对象、使魔、式神 | `relationships` / `inventory` / `abilities` | 必须有原著对应对象或召唤体系 |

## 7. 奖励完整性

### 7.1 完整奖励原则

奖励本体必须完整。

允许：

- 完整物品。
- 完整体质。
- 完整能力。
- 完整技艺。
- 完整知识。
- 完整道具。
- 完整血统。
- 完整流派传承。
- 完整资源体系。

禁止：

- 术式残片。
- 神器碎片。
- 血统种子。
- 试用版能力。
- 不完整功法。
- 只有一个招式、但没有所属流派基础的孤立技艺。

强奖励可以需要训练、适配、资源或身体条件才能发挥效果，但奖励本体仍是完整奖励。

### 7.2 技艺与流派规则

技艺、招式、武学、术式类奖励不能作为无根孤立招式发放。

默认规则：

- 奖励单个招式时，必须附带其所属流派、基础理论、入门训练法和必要前置条件。
- 奖励流派时，可以包含基础功、核心招式、进阶招式、禁招、身法、呼吸法、发力法、修炼禁忌。
- 如果某招式必须依赖特定体质、武器、资源或世界法则，则同步写入限制。
- 招式可以不会立刻熟练，但奖励本体必须完整。

示例：

| 不推荐 | 推荐 |
|--------|------|
| 获得天翔龙闪 | 获得浪客剑心世界 · 飞天御剑流传承，其中包含天翔龙闪，并补足最低使用门槛 |
| 获得雷之呼吸一之型 | 获得鬼灭世界 · 雷之呼吸传承，当前可优先修炼一之型 |
| 获得螺旋丸 | 获得火影世界 · 查克拉形态变化训练法与螺旋丸完整修炼路径 |

## 8. 成就等级与奖励分级

成就分等级，但**奖励战力分级必须直接复用角色卡与多世界战斗框架**：先按 `02-rating/02-evaluation-method.md` 的评价方式拆证据，再按 `02-rating/03-rating-system.md` 的项目内汪吧风格 N0–N24 评级表映射等级；不得另起 `mundane / supernatural / top-tier` 等独立体系，也不得只读取 N 表后直接定级。

同时，成就等级不绑定固定 N 级。奖励范围必须以**当前世界等级**为锚点动态计算，而不是写死为 `minor = N0–N2` 这类固定区间。

### 8.1 当前世界等级锚点

每次抽奖励前，必须先确定当前世界等级：

```json
{
  "currentWorldRating": {
    "rating": "N6 城镇级",
    "score": 5200,
    "basis": "当前剧情主要战斗与奖励承载环境约为城镇级。"
  },
  "currentWorldTopRating": {
    "rating": "N8 山脉/区域级",
    "score": 24000,
    "basis": "当前世界已知顶尖存在或顶级奖励约为区域级。"
  }
}
```

定义：

- `currentWorldRating`：当前剧情所在世界/篇章的常规战斗等级锚点。
- `currentWorldTopRating`：当前世界已知或允许触及的顶尖等级上限。
- 如果当前世界内部跨度很大，按当前篇章、当前地图、当前主线阶段取锚点，不直接取最终 boss 上限。
- 奖励来自其他世界时，也必须先用当前世界等级判断“现在能抽到多强、能发挥多强”。

### 8.2 成就等级的相对奖励范围

成就等级只决定相对当前世界等级的浮动范围。

| 成就等级 | 含义 | 默认奖励范围 | 最高可触及 |
|----------|------|--------------|------------|
| `minor` | 小成就，常规探索、低风险行动、轻度突破 | 当前世界锚点 -3 到 -2 N级 | 当前世界锚点 -1 N级 |
| `standard` | 标准成就，完成有风险目标或稳定突破 | 当前世界锚点 -2 到 -1 N级 | 当前世界锚点同级 |
| `major` | 重大成就，关键战斗、重要剧情节点、生死危机 | 当前世界锚点 -1 到同级 | 当前世界锚点 +1 N级 |
| `epic` | 史诗成就，改变局势、击败强敌、跨世界重大突破 | 当前世界锚点同级到 +1 N级 | 当前世界锚点 +2 N级，但不超过当前世界顶尖 |
| `legendary` | 传说成就，世界级或跨世界级重大事件 | 当前世界锚点 +1 到当前世界顶尖 | 当前世界顶尖 N级 |
| `mythic` | 神话成就，极罕见，只用于超高危或超长期成就 | 当前世界顶尖附近 | 当前世界顶尖 N级；特殊情况下可接近来源原著极限，但需严格论证 |

计算规则：

- N级下限不能低于 N0。
- N级上限默认不能超过 `currentWorldTopRating`。
- `minor / standard / major / epic / legendary / mythic` 的奖励强度随当前世界升级而水涨船高。
- 同一个 `major` 成就，在 N3 世界可能抽到 N2–N4 奖励；在 N8 世界则可能抽到 N7–N9 奖励。
- 当前世界等级变化后，后续即时生成候选的强度范围也随之变化。
- 不能因为成就等级叫 `legendary` 就固定抽 N9 或更高；它只代表“相对当前世界”的传说级。

### 8.5 上限规则

- 奖励不得超过当前世界顶尖水平太多。
- “当前世界顶尖水平”必须用同一套 N 级记录，例如 `currentWorldTopRating: N8 山脉/区域级`。
- 来源世界顶尖等级只用于判断奖励原著上限，不直接决定当前可抽奖励强度。
- 抽到来源世界极强奖励时，不削成碎片，但可要求更高成就等级、延后领取、提高适配难度、增加使用代价或标记为 `adaptationRequired`。
- 如果奖励本体在原著中就是顶尖级，允许完整发放，但主角当前表现不得立刻超过当前世界顶尖太多。
- 最低使用门槛补足只补到“能用”，不补到“无上限精通”。
- 如果奖励包含对应时间段使用者经验，也只获得当前世界等级允许承载的对应 N 级水平，不自动超越后期巅峰。
- N17 以上高维/宇宙结构级奖励必须有明确世界观结构证据，不能只凭“无限”“全能”“超越”等词定级。
## 9. 多重骰子随机获取

奖励通过多重骰子随机获取，不由 agent 直接挑选。

### 9.1 默认随机层级

```text
1. 掷骰确定奖励来源范围
   - currentWorld / visitedWorld / unvisitedWorld / canonIndex。

2. 掷骰确定成就等级 / 奖励强度范围
   - minor / standard / major / epic / legendary / mythic。

3. 掷骰确定奖励大类
   - item / constitution / ability / technique / knowledge / resourceSystem / resistance / summonOrContract。

4. 生成世界 `.rd100` 随机表
   - 已归档世界每个 3 个位置。
   - 未归档世界每个 2 个位置。
   - 剩余位置用其他随机动漫 / 游戏世界填满。
   - 所有位置随机打散。

5. 掷骰确定作品 / 世界候选来源
   - archivedWorld / unarchivedWorld / randomAnimeGameWorld。

6. 掷骰确定具体作品或世界
   - 已归档世界可直接进入候选。
   - 未归档世界或其他随机动漫 / 游戏候选必须先联网核实作品存在。

7. 联网核实具体奖励存在
   - 必须确认奖励名称、奖励形态、原著出处真实存在。
   - 核实失败则该候选无效，重骰具体奖励或重骰作品。

8. 掷骰确定具体奖励
   - 不从预置基础池抽取；命中世界后即时生成候选。
   - 即时生成候选必须有原著依据；未归档 / 随机动漫游戏候选必须生成临时 `webVerified` 候选记录后才能命中。

9. 掷骰确定获取形式
   - 物品入手 / 传承继承 / 身体改造 / 知识植入 / 契约建立 / 经验灌输。

10. 奖励进入待领取状态
   - 默认 `pendingClaim`。

11. 主角手动领取
   - 领取后执行最低门槛补足与多世界框架适配。
```

### 9.2 骰子记录要求

- 每一层随机都要记录骰面、表名、命中项。
- 已归档即时奖励候选必须事先存在；未归档世界或其他随机动漫 / 游戏候选必须先联网核实并生成临时验证条目，不能未经核实临场编造。
- 如果骰到不满足原著依据或联网核实失败的条目，视为无效项并重骰同一层。
- 如果骰到当前剧情暂时不适合公开使用的奖励，不删除奖励，而是记录为 `pendingClaim` 或 `adaptationRequired`。

建议使用 `packages/rp-random` 的 `rollTable` 或 `rollAnka` 进行多层表抽取。

---

### 9.3 世界 `.rd100` 随机表生成规则

世界随机表使用 `.rd100` 百分表。该表不是固定世界清单，而是每次按当前世界等级、已归档状态、未归档候选和随机动漫 / 游戏候选动态生成。


#### 9.3.1 生成顺序

```text
1. 确定当前世界等级锚点
   - 使用 currentWorldRating / currentWorldTopRating。

2. 过滤世界等级
   - 候选世界等级必须能承载本次成就等级允许的奖励范围。
   - 如果世界等级不对，剔除并替换为“随机动漫 / 游戏世界”候选。

3. 加入已归档世界
   - 每个符合等级的已归档世界占 3 个位置。
   - 已归档世界不需要联网核实作品存在。

4. 加入未归档候选世界
   - 每个符合等级的未归档世界占 2 个位置。
   - 未归档世界命中后必须联网核实作品和具体奖励存在。

5. 填充剩余位置
   - 剩余位置全部用“其他随机动漫 / 游戏世界”填充。
   - 命中后再随机确定具体动漫 / 游戏世界，并联网核实。

6. 随机分布
   - 所有位置必须随机打散，不按已归档 / 未归档 / 其他来源分段排列。
```

#### 9.3.2 位置权重

| 世界来源 | 每个世界占位 | 核实要求 |
|----------|--------------|----------|
| 已归档世界 | 3 个位置 | 不需要联网核实作品存在 |
| 未归档世界 | 2 个位置 | 命中后必须联网核实作品和奖励存在 |
| 其他随机动漫 / 游戏世界 | 填满剩余位置 | 命中后必须联网核实作品和奖励存在 |

如果符合等级的已归档世界和未归档候选过多，超过 100 个位置，则先按当前世界等级、当前剧情主题、奖励类型过滤；仍超过时，从同类候选中随机抽取进入本次 `.rd100`，但进入表内的已归档世界仍各占 3 个位置，未归档世界仍各占 2 个位置。

#### 9.3.3 世界等级不匹配替换

世界等级不匹配包括：

- 世界整体等级过低，无法合理承载本次奖励范围。
- 世界整体等级过高，命中后容易超过当前世界顶尖水平太多。
- 当前剧情阶段不适合引入该世界的奖励等级。
- 该世界缺少本次奖励类型所需的原著奖励。

处理方式：

```text
命中世界 → 检查等级 → 不匹配 → 替换为其他随机动漫 / 游戏世界 → 联网核实 → 再进入具体奖励抽取
```

#### 9.3.4 已有奖励去重

已有奖励不能重复。

规则：

- 抽奖前读取主角 `achievements`、`abilities`、`inventory`、`knowledge`、`resources`、`relationships` 等模块。
- 建立 `ownedRewardIds` / `claimedRewardIds` / `pendingRewardIds` 去重集合。
- 如果抽到已拥有、已领取或待领取的奖励，必须重骰具体奖励。
- 如果某个世界下可抽奖励全部重复，则重骰世界。
- 同名不同版本奖励必须检查是否确实是原著不同奖励；否则按重复处理。

建议记录：

```json
{
  "dedupe": {
    "ownedRewardIds": [],
    "claimedRewardIds": [],
    "pendingRewardIds": [],
    "rerollOnDuplicate": true
  }
}
```

#### 9.3.5 `.rd100` 表记录格式

```json
{
  "worldRollTable": {
    "type": ".rd100",
    "currentWorldRating": { "rating": "N6 城镇级", "score": 5200 },
    "currentWorldTopRating": { "rating": "N8 山脉/区域级", "score": 24000 },
    "slots": [
      { "roll": 1, "source": "archivedWorld", "world": "火影忍者", "slug": "naruto" },
      { "roll": 2, "source": "archivedWorld", "world": "火影忍者", "slug": "naruto" },
      { "roll": 3, "source": "archivedWorld", "world": "火影忍者", "slug": "naruto" },
      { "roll": 4, "source": "unarchivedWorld", "world": "待定未归档候选", "requiresWebVerification": true },
      { "roll": 100, "source": "randomAnimeGameWorld", "world": null, "requiresWebVerification": true }
    ],
    "shuffle": true
  }
```

## 10. 奖励手动领取

奖励不会自动进入主角身体、背包或能力栏，必须手动领取。

流程：

```text
成就达成
→ 奖励生成
→ 奖励进入待领取列表
→ 主角主动领取
→ 执行最低门槛补足
→ 多世界框架适配
→ 写入角色卡模块
```

规则：

- 成就达成只产生“待领取奖励”。
- 主角未领取前，奖励不生效。
- 主角领取时才进行身体补足、知识灌输、经验导入、资源补足或物品入手。
- 如果奖励会造成身体变化、经验灌输或资源体系接入，应在领取时明确提示。
- 奖励领取后才写入对应角色卡模块。

## 11. 最低使用门槛自动补足

### 11.1 原则

奖励发放后，如果当前角色不满足使用要求，系统必须把角色提升到满足“最低可使用要求”的程度。

这不是额外奖励，而是该奖励的必要配套。

最低使用门槛可以包括：

- 最低资源量。
- 最低资源感知能力。
- 最低控制技巧。
- 最低身体强度。
- 最低经脉 / 回路 / 查克拉 / 念 / 气 / 咒力等体系接口。
- 最低经验、境界、熟练度。
- 必要的基础理论和训练记忆。
- 必要武器、媒介或施术条件。

补足原则：

- 只补到“能使用该奖励的最低程度”。
- 如果奖励本身是完整流派或完整传承，则补足到能使用该传承核心内容的最低门槛。
- 如果奖励明确包含原著使用者经验，则可获得对应时间段使用者的经验、境界、身体最低条件。
- 补足内容必须写入对应模块，如 `resources`、`abilities`、`attributes`、`lifeProfile`、`knowledge`、`worldAdaptation`。
- 补足后仍可存在熟练度、耐久、消耗、世界适配等限制。

### 11.2 替身术示例

如果获得 `火影世界 · 替身术`：

- 奖励本体：完整的替身术。
- 自动补足：能施展一次替身术的最低查克拉量。
- 自动补足：替身术所需的最低查克拉操控技巧。
- 自动补足：术式发动所需的基础印、替换判断、时机记忆。
- 落盘：`abilities` 写入替身术，`resources` 写入最低查克拉，`knowledge` 写入基础施术知识。

### 11.3 飞天御剑流示例

如果获得 `浪客剑心世界 · 飞天御剑流`：

- 奖励本体：完整飞天御剑流传承，而不是单个招式。
- 自动补足：对应时间段使用者的全部经验、境界、招式理解。
- 自动补足：最低能用出奥义的身体条件。
- 自动补足：流派身法、发力逻辑、拔刀术基础、战斗判断。
- 落盘：`abilities` 写入飞天御剑流，`attributes` / `lifeProfile` 写入身体最低条件，`knowledge` 写入流派理论。

## 12. 多世界战斗框架挂钩

成就奖励与多世界战斗框架的关系不是“新增系统概念”，而是“把原著奖励翻译成角色卡可记录、可使用、可限制的模块变化”。

### 12.1 落地判定

奖励进入角色后，必须判定：

1. **原著来源**：奖励来自哪部作品？原著正式名称是什么？
2. **奖励类型**：实物 / 体质血统 / 能力术式 / 技艺流派 / 知识记忆 / 资源体系 / 召唤契约。
3. **战斗等级**：奖励对应角色卡同款 N0–N24 汪吧风格评级中的哪一级？
4. **框架映射**：应写入哪个角色卡模块？
5. **最低使用门槛**：当前角色缺什么？系统需要补足到什么最低程度？
6. **使用条件**：资源、媒介、身体、知识、熟练、环境是否满足？
7. **兼容性**：当前世界是否压制、排异、误读或改变表现形式？
8. **代价/限制**：消耗、冷却、副作用、身体负荷、暴露风险。

### 12.2 模块映射

| 奖励 | 主要模块 | 辅助模块 |
|------|----------|----------|
| 原著实物 / 装备 / 道具 | `inventory` | `resources` / `states` |
| 体质 / 血统 / 器官 / 灵根 | `attributes` / `lifeProfile` | `states` / `resistances` / `resources` |
| 主动能力 / 被动能力 / 术式 | `abilities` | `resources` / `combatRating` / `knowledge` |
| 技艺 / 武学 / 职业技能 / 流派 | `abilities` | `combatRating` / `knowledge` / `attributes` |
| 知识 / 记忆 / 语言 / 修炼法 | `knowledge` | `abilities` / `resources` |
| 资源体系 / 能量体系 | `resources` | `attributes` / `knowledge` / `worldAdaptation` |
| 抗性 / 免疫 / 净化 | `resistances` | `states` / `lifeProfile` |
| 召唤物 / 契约对象 / 使魔 / 式神 | `relationships` / `abilities` | `resources` / `combatLog` |

`worldAdaptation` 只记录该原著奖励在当前世界如何表现、是否被压制、是否需要转换资源接口，不再作为独立奖励类型。

## 13. 奖励状态

| 状态 | 含义 |
|------|------|
| `pendingClaim` | 成就已达成，奖励已生成，但尚未领取 |
| `claimed` | 奖励已领取，等待落盘或适配 |
| `granted` | 系统已发放完整奖励 |
| `stored` | 奖励完整，但暂存未使用 |
| `trainingRequired` | 奖励完整，但需要训练才能发挥 |
| `adaptationRequired` | 奖励完整，但需要多世界框架适配 |
| `active` | 已可正常使用 |
| `unstable` | 可用但有副作用或失控风险 |
| `incompatible` | 当前世界或身体暂不兼容 |
| `converted` | 已被框架转换成本世界可用形态 |
| `consumed` | 已消耗 |

## 15. 即时奖励候选生成规则

本系统不维护可直接抽取的“基础奖励池”。奖励候选在成就触发后即时生成。

目录中的示例只用于说明字段格式，不是预置池：

```text
data/rp-achievements/examples/instant-candidates/
```

即时生成流程：

1. 根据当前世界等级与成就等级确定奖励强度范围。
2. 通过世界 `.rd100` 表命中来源世界。
3. 随机确定奖励类型。
4. 即时提出多个原著奖励候选。
5. 已归档世界可跳过作品存在核实；未归档/随机动漫游戏世界必须联网核实作品与奖励存在。
6. 检查 canon 字段、完整性、禁用泛系统概念、世界等级、重复奖励。
7. 只保留通过校验的候选，命中后进入 `pendingClaim`。

## 16. 质量检查

发放奖励前检查：

1. 成就是否真的触发？
2. 成就是否对主角触发，而不是 NPC？
3. 是否只显示达成提示，没有主动展开系统光屏？光屏主动呼出后是否只显示已达成成就、当前人物状态、可领取奖励？
4. 是否通过多重骰子随机命中奖励？
5. 即时奖励候选是否预先存在？
6. 奖励是否有原著明确依据？
7. 奖励是否为完整奖励？
8. 奖励类型是否属于允许范围？
9. 是否排除了系统化泛概念？
10. 奖励是否进入 `pendingClaim`，等待主角手动领取？
11. 当前角色是否满足最低使用门槛？若不满足，领取时是否自动补足？
12. 奖励是否超过当前世界顶尖水平太多？
13. 奖励是否以当前世界等级为锚点，并按角色卡同款 N0–N24 汪吧风格评级分级？
14. 如果奖励影响战力，是否记录到 `combatLog` 并更新 `combatRating` 证据？

## 17. 已确认决策

- 成就系统是可选独立模块，只给主角使用。
- 成就系统定位为主角专属外挂式奖励系统。
- 成就系统默认隐藏，只有达成时提示。
- 光屏默认不显示，需要主角主动呼出；呼出后只显示已达成成就、当前人物状态、可领取奖励。
- 系统没有任何主动能力。
- 奖励必须手动领取。
- 奖励必须是原著明确出现过的完整奖励，不能依托世界观虚构。
- 奖励必须通过多重骰子随机获取，并进入待领取状态。
- 掷骰确定作品 / 世界时，可以来自未归档世界或模型其他随机动漫 / 游戏候选，但必须联网核实作品和奖励真实存在。
- 角色不满足使用要求时，领取时自动补足到最低可使用程度。
- 奖励类型收窄为原著可验证内容，不使用泛系统概念。
- 奖励不得超过当前世界顶尖水平太多。
- 成就分等级，但奖励范围只与当前世界等级锚点有关，并动态映射到角色卡同款 N0–N24 汪吧风格评级。

## 18. 待确认问题

1. 是否缓存最近一次即时生成候选？建议只缓存本次结果与已验证来源，不维护基础池。
2. 多重骰子随机过程是否公开？建议公开奖励结果，隐藏未命中即时候选记录内容。
3. 成就提示是否显示奖励名，还是只显示“奖励待领取”？建议普通成就显示奖励名，隐藏成就只显示待领取。
