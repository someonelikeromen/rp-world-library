# 生命系统树：曙光/口述表信息来源使用约定

> 版本：1.2  
> 适用范围：`data/rp-life-system-tree/sources/` 中的曙光表、口述表合并数据与战力映射资料。  
> 核心定位：这些资料是**信息来源池 / 搜索语料 / 证据来源**，不是可直接点亮的节点库。

---

## 0. 总原则

曙光表、口述表、战力参考表、论战参考换算表**不是节点库**，而是生命系统树的**世界观信息来源池**。

它们的作用是：

1. 搜索能力、血统、道具、功法、技能时提供参考资料；
2. 提供无限系兑换体系下的定价、描述、前置、出处；
3. 辅助 LLM 判断该能力在多世界框架中的 N 级、成长边界、树结构位置；
4. 作为节点生成的证据来源之一。

**禁止：**

- 直接把 12,632 条兑换项批量转成生命系统树节点；
- 只凭支线价格机械映射 N 级；
- 只凭名称相同就认定为同一个节点；
- 只凭曙光/口述表的兑换价格就认定最终战力；
- 将普通外部装备、消耗品、主神功能直接当作生命系统树能力节点。

一句话约定：

> 曙光表与口述表只作为无限系来源资料库。搜索时返回候选资料，LLM 结合定价、描述、前置、战力参考表和 N0-N24 框架进行综合审核；只有审核通过的候选，才可生成生命系统树节点。

## 1. 数据分层

### 1.1 Raw Source：原始来源层

目录：

```text
data/rp-life-system-tree/sources/
├── merged_科技类.json
├── merged_魔法传说类.json
├── merged_辅助类.json
├── merged_娱乐类.json
├── 战力体系对照总表.json
├── 战力体系对照表.md
├── source-index.json
└── conversion-convention.md
```

这一层只代表：

> 这些资料中存在这样的兑换项、描述、价格、前置和分类。

它们不是节点，不进入 `global-graph.json`。

### 1.2 Search Corpus：搜索语料层

当用户搜索能力时，系统从来源池中检索候选。

示例：

- “搜索吸血鬼血统”
- “搜索念动力”
- “搜索可以控制时间的能力”
- “搜索科技类单兵武装”
- “搜索适合精神系主角的能力”

检索字段：

- 名称；
- 别名或近似名；
- 描述；
- 前置需求；
- 分类；
- 出处；
- 支线等级/积分；
- 口述表/曙光表来源差异。

返回的是**候选资料卡**，不是节点。

### 1.3 Evidence Bundle：证据包层

用户选中某个候选后，LLM 需要为它整理证据包。

证据包结构建议：

```json
{
  "candidateName": "",
  "sourceEntries": [
    {
      "source": "曙光表",
      "category": "",
      "rank": "",
      "cost": "",
      "prereq": "",
      "description": ""
    },
    {
      "source": "口述表",
      "category": "",
      "rank": "",
      "cost": "",
      "prereq": "",
      "description": ""
    }
  ],
  "powerReferences": {
    "exchangeRankMapping": "",
    "shuguangCombatTier": "",
    "vbTier": "",
    "nRatingRange": ""
  },
  "llmNotes": {
    "effectSummary": [],
    "limitations": [],
    "growthPotential": "",
    "crossWorldConcerns": "",
    "pricingConflicts": "",
    "descriptionConflicts": ""
  }
}
```

证据包是后续节点化的基础，不等于节点。

### 1.4 Audited Node：审核节点层

只有经过 LLM 综合判定后，才能生成生命系统树节点。

生成后的节点才可以进入：

```text
data/rp-life-system-tree/global-graph.json
```

或当前角色的：

```text
card/<protagonist>/progression/life-system-tree.json
```

## 2. 搜索流程

### 2.1 搜索输入

用户可以按以下方式搜索：

| 搜索方式 | 示例 |
|---|---|
| 名称搜索 | “搜索念动力” |
| 类型搜索 | “搜索血统类能力” |
| 效果搜索 | “有没有复活能力” |
| 战力搜索 | “搜索 N6 左右的强化” |
| 体系搜索 | “搜索魔法传说类的能量基盘” |
| 前置搜索 | “以血族血统为前置的能力有哪些” |
| 组合搜索 | “搜索适合精神系、低副作用、N4以内的能力” |

### 2.2 搜索输出

搜索结果应输出为候选资料卡：

```text
候选 1：念动力
分类：辅助类 / 技能
来源：曙光表、口述表
支线/价格：B / 3000点
初步 N 级：N4 左右，仅作为价格先验
描述摘要：……
前置需求：……
LLM提示：可能是能力节点，不是能量基盘；需判断上限与成长性。
```

措辞规则：

- 可以说“初步 N 级”或“价格先验 N 级”；
- 不可以说“该节点就是 N4”；
- 不可以直接显示为可点亮节点；
- 不可以跳过用户确认直接写入节点。

## 3. LLM 综合判定流程

LLM 判断一个候选能否转成节点时，按以下顺序。

### 3.1 第一步：确认它是什么

先判断候选类型。

| 类型 | 说明 | 是否可成为节点 |
|---|---|---|
| 血统 | 改变生命本质或种族 | 可作为基点 |
| 体质 | 改变身体/灵魂基础 | 可作为基点 |
| 能量基盘 | 提供内力、魔力、真气、查克拉等 | 可作为基点 |
| 职业/传承 | 带完整成长路线 | 可作为基点或树干 |
| 技能 | 单个能力 | 通常是子节点 |
| 功法 | 可修炼体系 | 可能是基点或树干 |
| 武器 | 外部装备 | 通常不是生命节点，除非绑定/融合/内化 |
| 道具 | 外物或消耗品 | 通常只做来源，不做生命节点 |
| 知识 | 可学习内容 | 可做知识节点 |
| 主神功能 | 系统功能 | 默认不可作为生命节点 |
| 说明/分类行 | 非能力 | 不转换 |

关键规则：生命系统树强调“生命变化、能力成长、真实掌握”。

因此：

- “血族血统”可以是节点；
- “高斯步枪”通常不是生命节点；
- “枪斗术”可以是技能节点；
- “魔法书”本身不是节点，但书中可学习的魔法可以是节点；
- “主神修复”不是节点；
- “永久性灵魂改造”可以是节点。

### 3.2 第二步：确认来源可信度

| 情况 | 处理 |
|---|---|
| 曙光表、口述表都有 | 双来源，可信度高 |
| 仅口述表 | 可信，但标记 `only_口述表` |
| 仅曙光表 | 可信，但标记 `only_曙光表` |
| 两表冲突 | 记录冲突，不自动合并 |
| 描述不清 | 需要 LLM 保守判断 |
| 明确“待调整/仅介绍/表现不明” | 不转节点或标记低可信 |

### 3.3 第三步：提取能力效果

LLM 从描述中提取：

```json
{
  "effects": [
    {
      "type": "攻击/防御/速度/感知/恢复/精神/空间/时间/因果/召唤/变身/能量/知识",
      "summary": "",
      "combatImpact": "",
      "nonCombatImpact": "",
      "conditions": "",
      "limitations": ""
    }
  ]
}
```

重点提取：

- 攻击力是否提升；
- 是否提供能量体系；
- 是否改变寿命；
- 是否影响灵魂；
- 是否带来抗性；
- 是否有代价；
- 是否有副作用；
- 是否有成长线；
- 是否需要外物、仪式、环境或血统前置。

### 3.4 第四步：判断 N 级

N 级不是简单由价格决定，而是综合判定。

#### 参考因素权重

| 因素 | 权重 | 说明 |
|---|---:|---|
| 描述表现力 | 最高 | 实际能力描述优先 |
| 支线/价格 | 高 | 无限兑换体系内的定价先验 |
| 战力参考表 | 高 | 曙光体系战力标准 |
| 论战换算表 | 高 | VB Tier / 能量范围参考 |
| 前置需求 | 中 | 高前置通常意味着高阶成长 |
| 原作出处 | 中 | 如描述涉及特定世界强度 |
| 分类 | 低 | 科技/魔法/辅助只作类型，不直接决定 N |

#### 推荐流程

```text
1. 读取支线/积分，得到价格先验 N 区间；
2. 读取描述，判断实际效果；
3. 对照曙光战力参考表，确认是否匹配该阶表现；
4. 如有明确破坏力、速度、防御、范围，使用论战换算表校验；
5. 如定价与描述冲突，优先描述，但记录定价异常；
6. 输出 baseN、peakN、conditionalN。
```

#### 输出格式

```json
{
  "nRating": {
    "base": "N4",
    "peak": "N5",
    "conditional": "N6 if fully unlocked / requires XXX",
    "pricingPrior": "B → N4",
    "descriptionCheck": "描述符合三阶到半步四阶",
    "confidence": "medium"
  }
}
```

## 4. 价格只能作为“先验”

支线和积分不能直接等于最终 N 级。

| 情况 | 处理 |
|---|---|
| C级但描述能毁城 | 描述超标，需上调或标记异常 |
| S级但只是一次性道具 | 不一定作为高 N 生命节点 |
| 高价是因为稀有/剧情价值 | 不一定提高战力 N |
| 低价但有巨大成长潜力 | baseN低，peakN高 |
| 装备强但使用者不掌握能力 | 不直接提升生命树本体 N |

N 级应拆分：

| 字段 | 含义 |
|---|---|
| `pricingPriorN` | 按兑换价格推测的 N |
| `effectN` | 按描述实际效果推测的 N |
| `growthPeakN` | 完整成长上限 |
| `usableN` | 当前可用实际强度 |
| `finalSuggestedN` | LLM 综合推荐 |

## 5. 树结构判定

### 5.1 基点

可以作为能力基点的情况：

- 血统起点；
- 能量体系起点；
- 职业传承起点；
- 体质/灵魂/生命形态改变；
- 可长期成长的功法；
- 可构成后续分支的核心能力。

示例：

```text
血族血统
念动力
修真功法
魔力回路
查克拉体系
精神力控制者
```

### 5.2 子节点

通常作为子节点的情况：

- 单个技能；
- 单个招式；
- 某血统的进阶能力；
- 某能量体系下的术法；
- 某职业的专精能力；
- 某装备绑定后的附加能力。

### 5.3 非节点，仅来源

通常不进入生命系统树：

- 一次性消耗品；
- 普通外部装备；
- 主神服务；
- 价格说明；
- 分类标题；
- 剧情解释；
- 纯材料；
- 没有被主角内化的道具。

但它们仍然可以作为：

- 搜索结果；
- 兑换参考；
- 剧情道具；
- 节点生成证据；
- 能力来源说明。

## 6. 同名项处理

同名项不能简单合并。

### 6.1 两表同名

输出：

```json
{
  "name": "",
  "versions": {
    "曙光表": {},
    "口述表": {}
  },
  "comparison": {
    "sameConcept": true,
    "pricingDifference": "",
    "descriptionDifference": "",
    "recommendedBase": "口述表",
    "notes": ""
  }
}
```

推荐规则：

| 冲突 | 处理 |
|---|---|
| 定价不同 | 记录两者，口述表为新版先验 |
| 描述不同 | 保留两版，LLM 综合 |
| 前置不同 | 合并并标记差异 |
| 效果不同 | 可能拆成两个版本 |
| 名称相同但实际不同 | 不合并，建立 disambiguation |

### 6.2 名称相似

例如：

- “念动力”
- “高级念动力”
- “念动力强化”
- “念动力控制者”

不能自动合并，需要判断是：

1. 同一树的进阶；
2. 同名不同体系；
3. 旧版/新版；
4. 相似但无关。

## 7. 生命系统树节点生成前检查表

LLM 在真正生成节点前必须检查：

```text
[ ] 是否是能力/体质/能量/知识/传承，而不是纯道具？
[ ] 是否有清晰来源？
[ ] 是否有描述文本？
[ ] 是否有价格先验？
[ ] 是否能估算 N 级？
[ ] 是否有前置？
[ ] 是否存在同名版本冲突？
[ ] 是否适合生命系统树，而不是兑换系统？
[ ] 是否需要跨世界适配？
[ ] 是否有副作用、限制或条件？
```

如果关键项缺失，应返回“候选不足，暂不生成节点”。

## 9. 不转换/慎转换规则

### 9.1 不转换

以下条目不转换为生命系统树节点：

- 分类目录行；
- 系列标签；
- 纯说明、免责声明、价格规则；
- 主神服务；
- 一次性消耗品；
- 普通外部装备；
- 无描述或描述仅为分类名；
- 明确标记“仅介绍”“待调整”“表现不明且价格不予参考”。

### 9.2 慎转换

以下条目需要额外说明后才可节点化：

- 装备：只有绑定、融合、内化、变成身体能力时才可进入生命树；
- 知识/秘籍：需要能被主角学习并长期掌握；
- 道具：只有造成永久体质/灵魂/生命形态变化时才可节点化；
- 职业：需要确认是否只是兑换身份，还是包含能力体系；
- 召唤/契约：默认属于关系/队友/使魔，不直接算主角生命节点，除非契约改变主角能力。

## 10. 搜索匹配约定

用户搜索时，按以下优先级匹配：

1. 名称精确匹配；
2. 名称包含关键词；
3. 描述包含关键词；
4. 前置需求包含关键词；
5. 分类筛选；
6. 效果语义匹配；
7. N 级或价格区间过滤。

返回时附带：名称、支线、价格先验 N、分类、来源、描述摘要、前置需求、冲突提示。最多 10 条。
