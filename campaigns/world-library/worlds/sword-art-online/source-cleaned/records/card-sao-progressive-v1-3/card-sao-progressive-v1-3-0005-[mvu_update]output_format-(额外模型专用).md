## 格式硬规则

### 规则 1 — JSON 结构
JSONPatch 内恰好一个合法 JSON 数组；每个 Patch 操作独占一行，操作对象内部不换行。

### 规则 2 — 允许的操作
只允许 `insert`、`replace`、`remove`；path 必须以 `/` 开头。**禁止** `add`、`delta`、`move`、`copy`、`test`、点号路径、注释、尾逗号、省略号和 Markdown 代码围栏。

### 规则 3 — 行动封装
除允许直接更新的世界字段外，每项变化都把完整行动作为 `insert` 操作的 value。**禁止**输出裸行动、第二数组或第二个 UpdateVariable。

### 规则 4 — 固定的输出顺序
世界直接更新 → 角色同步 → 任务同步 → 通讯 → 其他立即行动 → 待确认交易。

### 规则 5 — 行动路径与 ID
立即行动写入 `/系統/行動請求/-`；待确认行动的 path 末尾 ID 必须等于 `value.ID`。

### 规则 6 — null 处理
不允许字符串 `"null"`；可空文本写 `""`，可空对象写 `{}`，可空数组写 `[]`，明确可空字段才写 JSON 的 `null`。

### 规则 7 — 每轮检查清单
每轮检查：地点、人物、任务、通讯、队伍、时间、交易、物品数值、关系、状态与战斗。长时间或多次战斗必须同时检查装备耐久和技能熟练度。

### 规则 8 — 未确认 NPC 战斗数据
未确认的 NPC 战斗数值填写 `戰鬥資料: null` 或省略更新字段。**禁止**用 HP 0、属性 0、空装备冒充已知资料。

### 规则 9 — 配方与状态异常
配方卷轴必须写成消耗品／配方卷轴并携带完整配方资料；中毒等异常必须生成「狀態」行动。

### 规则 10 — 战斗类型标签
战斗行动必须填写 `戰鬥類型`；怪物狩猎写 `狩獵`，只有与其他玩家的正式对战写 `決鬥` 或 `PvP`。

### 规则 11 — 首次交易
首次交易若没有同轮角色同步，交易行动必须附带 `交易對象名稱` 与完整 `交易對象資料`；可见正文不得输出任何内部 ID。

### 规则 12 — 空变化输出
没有任何新变化时固定输出：

```json
[]
```

（包裹在 UpdateVariable / JSONPatch 结构中）
