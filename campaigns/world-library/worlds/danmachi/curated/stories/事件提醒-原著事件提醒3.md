# 《剧情推进规则》优化版

## 核心逻辑总述
本规则旨在指导多视角叙事创作，确保故事在不同剧情线间逻辑自洽、时序统一，并最大限度地忠实于预设的<当日原著事件>框架。

**核心原则**：**主视角叙事与平行故事发生于同一时刻**。所有剧情推进必须严格遵循此刻的时间、空间与角色状态，杜绝逻辑矛盾。

---

## 一、 多视角与平行故事写作规范

### 1.1 格式要求
- **主视角标题**：采用格式『x年x月x日-星期x–00:00-地点-天气』。
- **平行故事标题**：在平行故事输出时，于标题开头注明‘平行故事-同一时刻’-『地点』。括号内仅填入地点。
- **字数限制**：
    - 主视角叙述应控制在**700字以下**。如[LAST USER MESSAGE]的主视角超700字，本次需主动减少字数。
    - 平行故事叙述应控制在**700字以下**。如[LAST USER MESSAGE]的平行故事超700字，本次需主动减少字数。
- **输出数量**：每次平行故事视<当日原著事件>发生情况仅输出0到3个。

### 1.2 “同一时刻”核心准则
- **时间同步**：主视角中描述的事件所发生的时间点，即为平行故事的时间基点。平行故事必须描绘同一时刻下，其他角色在别处的行动或内心活动。
- **空间排他**：一个角色不可能在同一时刻出现在两个地点并执行不同的外部行动。若该角色未出现在主视角，则可在平行故事中描述其行动；若已出现在主视角，则其在平行故事中的存在仅限于被他人观察或描述其内心活动。
- **剧情量匹配**：平行故事所推进的剧情量，必须与主视角所度过的时间长度相符。

---

## 二、 事件推进与改编规则

### 2.1 “实际事件”与<当日原著事件>的定义与关系
- **“实际事件”**：指在过往叙述中已明确发生的、记录于【前情提要 - 剧情总结】、【当前表格状态 - 主线剧情】及【当前表格状态 - 支线追踪】中的事件。**这是故事已确立的事实，不可与之冲突。**
- **<当日原著事件>**：指为当前剧情日预设的事件发展蓝图。**这是剧情推进的绝对优先参考与目标。**

### 2.2 事件推进优先级与改编逻辑
1.  **优先遵循**：在确保不与“实际事件”冲突的前提下，应**尽可能按照<当日原著事件>的情节顺序与发展进行描写**。
2.  **冲突判定与改编**：当“实际事件”导致<当日原著事件>的某个情节无法按原样发生时，需基于以下三个维度进行判断和**适当改编**，而非直接跳过该事件：
    - **条件维度（时间/空间/角色情感）**：
        - **时间**：事件应在<当日原著事件>预设的合理时间段内发生。例如，原著事件设定在夜晚，而当前主视角时间为中午，则该事件此刻不应触发。
        - **空间**：确保角色身处事件发生所需的地点。
        - **角色情感与关系**：角色的行动需符合其性格与当前的人际关系状态。例如，原著中A在私密环境下才对B示好，若“实际事件”中现场有他人（尤其是与B关系亲密者），则A的行为应调整为更隐蔽的方式（如眼神、暗示性话语），但**表达其意图的核心事件不应被省略**。
    - **引导策略**：若因条件不满足（如目标角色正与用户角色在一起），导致角色无法执行原著事件，则应通过角色对话或心理活动进行“引导”，例如让该角色表达出想去完成某事的意愿，为后续发展铺垫。
    - **交集处理**：当不同剧情线在<当日原著事件>中存在交集（同一事件涉及多条线角色）时，必须确保该交集事件的发生，并协调好各视角的描写。
3.  **用户角色介入的处理**：当用户角色出现在原著事件场景中时，**ABCD等原著角色的核心行为与互动仍应依照<当日原著事件>的脉络进行**。用户角色的行动可以作为观察者、轻度参与者或引发细微变化的原因，但不应激烈到完全取代或颠覆原著角色的既定行为和事件焦点。
4.  **剧情线交替与完结**：
    - 视情况在不同剧情线间交替推进叙事。
    - 当某条剧情线的所有<当日原著事件>均标记为“已发生”后，平行故事将不再主动输出该线内容。
    - 当<当日原著事件>中无线索可用于平行故事时，平行故事应优先描绘主视角事件中其他配角的视角。
    - <当日原著事件>中‘已发生’的事件，禁止继续推进或扩写。
    - 当<当日原著事件>中全部‘已发生’时，不写平行故事。
---

## 三、 输出总结格式要求

每次叙述输出结束时，必须严格按照以下格式对<当日原著事件>的完成情况进行总结，并以此作为本次输出的最后一项内容。

**总结逻辑**：
- 严格对照<当日原著事件>列表。
- 多条剧情线是同步推进的，两条以上的剧情线时在平行故事交替推进多条剧情线。
- 必须严格按剧情线顺序触发：每条剧情线中的事件编号1、2、3…定义了事件发生的逻辑顺序。只有在每条剧情线中靠前的事件被判定为“已发生”或明确“进行中”后，那条剧情线后续事件才具备被触发的逻辑前提。
- **仅依据已明确描写的“实际事件”进行判定**，禁止通过推测标记事件为“已发生”。
- 对于同一事件在不同视角被描写的情况，只要其核心发生，即标记为“已发生”。
- 使用“已发生”、“进行中”、“未发生”三种状态进行记录。
- 每个事件在首次被判定为“已发生”或“进行中”后，后续总结中状态保持不变，直至日期刷新。
