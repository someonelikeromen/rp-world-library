## 后续强制爬取频率

后续对 Wenku8 或类似文库站点统一使用低频、可恢复策略：

1. **禁止全站并发 ID 扫描**
   - 不再用 16 并发或批量扫 ID。
   - 若必须探测 ID，最多单线程，且每次只探测少量明确候选。

2. **请求间隔**
   - 目录页：每次请求后等待 **8–12 秒**。
   - 章节正文页：每次请求后等待 **12–20 秒**。
   - 失败、302 登录页、429/403/Cloudflare、连接异常后：等待 **10–30 分钟** 后再继续。

3. **单批上限**
   - 每批最多抓取 **1 个 index 页 + 5 个章节页**。
   - 每批完成后至少暂停 **5 分钟**。
   - 大卷正文抓取必须支持断点续爬，不允许一次性全站/全卷硬拉。

4. **入口优先级**
   - 优先使用已知作品入口、搜索引擎缓存、已有 TOC、项目中保存过的 URL。
   - 不优先用 Wenku8 搜索接口，因为搜索/列表页常要求登录或触发验证。
   - 不用全站 ID 暴力扫描作为默认手段。

5. **必须保存爬取状态**
   - 保存 `toc.json` / `chapters.json` / `crawl-state.json`。
   - 每个章节下载后立即写盘，记录 URL、标题、卷、抓取时间、HTTP 状态。
   - 已完成章节下次跳过。

6. **User-Agent 与礼貌策略**
   - 使用普通浏览器 UA。
   - 不绕过验证码/登录限制；出现验证即暂停并记录。
   - 不要高频重试同一 URL。

## 对亚里亚任务的下一步建议

1. 先暂停 Wenku8 访问，避免继续触发风控。
2. 通过低频方式或外部已知入口定位《绯弹的亚里亚》Wenku8 index。
3. 先只抓取 TOC，登记到 `source-registry.json`，标注 `A-for-toc-only`。
4. 再按卷分批抓正文，每批少量章节并断点续爬。
5. 正文入库后再进行 characters/world/plot graph 源验证。
